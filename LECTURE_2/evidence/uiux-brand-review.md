# LECTURE_2 로고·심볼·글꼴 확장 독립 UIUX 검수

검수일: 2026-10-20. 실행 주소: `http://127.0.0.1:49323/`. Windows의 설치된 Chrome을 별도 Playwright 컨텍스트로 실행하여 1440×1000, 390×844 화면에서 확인했다. 제품 코드는 수정하지 않았다.

## 판정: PASS — 검수한 확장 제작 흐름

검수한 범위의 남은 P1/P2는 없다. 발견한 모바일 로고 최소너비 불일치는 수정 후 실제 치수로 재검수했다. 이 판정은 아래의 실제 확인 범위에 한정하며, 전체 접근성 적합성이나 모든 글꼴 형식·운영환경 검증을 뜻하지 않는다.

사용자는 로고·심볼·글꼴이 있으면 원본을 넣고 구체적인 사용 규칙을 기록해야 하며, 파일이 없으면 기본값으로 계속 완성할 수 있어야 한다. 따라서 이번 확장의 첫 판단은 자산의 역할과 지정 여부이고, 다음 판단은 그 자산이 적용될 배경·크기·글자 역할이다. 현재 화면은 파일 선택을 의무화하지 않으며 기본 로고·어두운 배경용 로고·심볼, 본문·제목 글꼴을 각각 구분한다.

## 모의 상태로 확인한 범위

### 저장 실패와 복구

브라우저에서 검수 프로젝트의 저장 PUT 응답만 HTTP 500으로 대체했다. 실제 디스크 장애를 만들지는 않았다.

- 편집한 글꼴 메모가 화면에 유지되고 저장 실패가 표시됐다.
- 실제 JSON 백업 다운로드에 편집 메모, 로고 3종, 본문/제목 fontFiles가 포함됐다.
- 새로고침 후 임시 편집 메모와 두 글꼴 역할이 복구됐다.
- 저장 가로채기를 해제한 뒤 저장에 성공했고 본문/제목 모두 업로드 파일 로딩을 다시 확인했다.
- 장애 확인용 메모는 원래 메모로 돌려 저장했다.

### AI 제안 적용과 취소

실제 AI를 추가 호출하지 않았다. 검수 브라우저의 작업 생성·조회 응답을 가로채 디자인 원칙 한 항목을 바꾸는 완료 제안을 제공했다.

- UI에서 제안 비교 → 적용 → 취소를 실제 수행했다.
- 적용 후와 취소 후 모두 로고 3종과 fontAssets가 적용 전과 동일했다.
- 취소 후 design JSON 전체가 적용 직전과 정확히 동일했다.

이 검사는 프런트엔드 적용·취소의 자산 보존 확인이다. 실제 모델의 새 응답이나 서버의 fontSource 보존 로직을 이 모의 검사로 검증했다고 주장하지 않는다.

## 발견 후 수정된 P2

390px 화면에서 로고 최소너비 300px·보호여백 20px를 지정했을 때, 표본 문구는 300px였으나 이미지 실제 너비는 214px였다. `max-width:100%`가 지정 규격을 축소했다.

수정 후 같은 조건에서 실제 너비 300px를 확인했다. 표본의 내부 폭은 clientWidth 254px/scrollWidth 340px이고 overflow-x는 auto였다. 바깥 문서는 390px를 유지했다. 규격을 줄여 보이는 대신 표본 내부에서 실제 크기를 확인할 수 있다.

## 검수 프로젝트

기존 사용자 프로젝트 대신 아래 새 프로젝트만 사용했다.

- 업로드 원본: `e753bd23-74d7-4763-bade-e961000101ac`
- ZIP 재가져오기: `57ff0c47-e1bb-493c-85dd-7dde6894277a`
- 구버전 무파일 가져오기: `0420c487-5d0e-4551-8974-7acfb32931eb`

ZIP은 메모리에서 해석했으며 검수용 ZIP 파일을 별도로 남기지 않았다. 동일 프로젝트의 내보내기 API로 다시 받을 수 있다. 초기 검수 준비 중 생성된 이름 없는 검수 자료가 있을 수 있다.

## 미검증과 한계

- OTF·WOFF·WOFF2의 실제 정상 파일, 가변 글꼴, 모든 굵기 조합은 업로드 시험하지 않았다. 이번 실제 폰트 시험은 TTF Regular/Bold 두 파일이다.
- 새로운 실제 Codex/Claude 생성은 독립 검수에서 호출하지 않았다. 부모 작업자의 실제 생성 및 서버 단위 테스트 결과와 분리한다.
- 압축 해제된 사용자 폰트의 file:// 독립 실행, CRC 전체 검사 등은 부모 작업자가 따로 확인한 범위다. 여기서는 실제 ZIP 다운로드·파일 바이트·재가져오기를 직접 확인했다.
- 실제 OS 글꼴 설치 여부 판별, 다른 PC·OS·브라우저·실물 휴대전화, 네트워크 단절·실제 저장 공간 부족·권한 오류는 시험하지 않았다.
- 스크린리더 전체 검사, 모든 확대율·대비·긴 파일명 조합, 전체 WCAG 적합성을 보증하지 않는다.
- 파일 선택 중 프로젝트 전환 방지의 최종 추가 로직은 별도 지연 주입으로 재현하지 않았다.
- 라이선스 메모는 사용자가 제공한 문장의 보존만 검증했다. 사용 권한에 대한 법률 판단과 최종 스킬 생성은 범위 밖이다.

추가 모델 호출과 실제 장애 유발은 생략했다. 검수한 선택 자산·세부 글꼴·내보내기·복구 흐름은 PASS이며 위 한계는 남는다.
