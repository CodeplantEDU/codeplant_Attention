# LECTURE 2 · CODEPLANT 디자인 스튜디오

**첫 번째 실습: 나만의 디자인 시스템 만들기.** 기획을 한국어로 적고, 색상·글꼴·여백·컴포넌트 규칙을 편집한 뒤 Codex에서 스킬로 만들 자료를 내보내는 로컬 웹 서비스입니다.

## 실행하기

Node.js **22 이상**이 필요합니다. npm 패키지를 따로 설치하지 않습니다.

1. 이 저장소를 내려받아 `LECTURE_2` 폴더를 여세요.
2. Windows는 **실행.cmd**를 실행합니다. Mac은 이 폴더에서 `npm start`를 실행합니다. `실행.command`를 쓰려면 먼저 `chmod +x 실행.command`를 실행하세요.
3. 브라우저에서 **http://127.0.0.1:49323**을 여세요. 서버 창을 켜 두세요. 종료는 서버 창에서 Ctrl+C입니다.

```sh
cd LECTURE_2
npm start
```

`LECTURE_1` 작업실과 다른 포트를 사용합니다. 다시 실행했을 때 같은 폴더의 서버가 이미 실행 중이면 기존 주소를 안내합니다. 다른 프로그램이 포트를 쓰는 경우 `DESIGN_PORT` 환경 변수로 변경하고 출력된 주소를 여세요.

## 수강생마다 자신의 계정으로 연결하기

**각자 자신의 PC에서 서버를 실행합니다.** 강사 PC의 서버 주소에 함께 접속하는 서비스가 아닙니다. 이 PC에 설치된 Codex와 Claude Code를 자동으로 찾아 버전과 저장된 로그인 상태를 확인합니다. CLI 파일을 찾았다는 것과 로그인 확인, 실제 응답 성공을 구분해 표시합니다.

화면 왼쪽 아래 **이 PC의 AI 연결**에서 상태를 확인하세요. 기존 로그인과 프로그램을 재사용하며 인증 파일을 복사하지 않습니다.

| 도구 | 없을 때 공식 패키지 설치 | 본인 계정 로그인 |
|---|---|---|
| Codex | `npm install -g @openai/codex` | `codex login` |
| Claude Code | `npm install -g @anthropic-ai/claude-code` | `claude auth login` |

**로그인 터미널 열기**를 누르거나 표시된 명령을 터미널에서 실행하세요. 본인이 공식 인증을 마친 뒤 **설치 · 로그인 새로 확인**을 누르세요. 앱은 설치 명령과 공식 안내를 제공하며 CLI를 임의로 설치·업데이트하거나 기존 계정을 로그아웃시키지 않습니다. 로그인 확인은 모델 사용 권한·잔여 사용량·네트워크 정상까지 보장하지 않습니다.

탐색 위치는 PATH, 사용자 `.local/bin`·`.cargo/bin`, npm 전역 설치 경로, 알려진 Codex 데스크톱 경로입니다. 시스템 정책 때문에 경로를 읽을 수 없으면 공식 CLI를 설치하거나 `DESIGN_CODEX_EXE`·`DESIGN_CLAUDE_EXE`에 실제 실행 파일의 절대 경로를 지정하세요. `.cmd`·`.bat`·`.ps1`을 실행 파일로 지정하지 마세요.

## 디자인 시스템 만들기

1. **방향 정하기**: 이름과 서비스 목적을 적습니다. 사용자·분위기·참고 글·출처·문서와 이미지 첨부는 선택입니다. 빈 내용은 실제 사실처럼 채우지 않습니다.
2. **디자인 규칙**: 로고·심볼, 의미별 색상 10개, 제목·본문 글꼴과 크기·굵기·행간·자간, 여백·모서리·너비, 한국어·아이콘·이미지 사용 규칙을 편집합니다. 오른쪽 예시 화면에 즉시 반영됩니다.
3. **적용해 보기**: 넓은 화면·모바일, 버튼·입력·오류·비활성·키보드 포커스를 확인합니다. 일반 글자 네 조합의 색상 대비를 자동 계산합니다. 자동 대비 결과는 전체 접근성 인증이 아닙니다.
4. **자료 내보내기**: 규칙·출처·화면 확인에 체크한 뒤 ZIP 또는 규칙 문서를 내려받습니다.

### 참고 문서·이미지 넣기

첫 단계의 **참고 문서·이미지 파일 선택** 버튼이나 큰 점선 영역에 여러 파일을 드래그앤드롭합니다. PDF·DOCX·PPTX·XLSX·HWPX·TXT·MD·CSV·JSON·CSS에서 텍스트를 읽습니다. PNG·JPG·WebP·HWP도 원본을 보관할 수 있습니다. 파일당 15 MB, 디자인당 20개·합계 60 MB입니다. 참고 JSON 문서는 참고 자료로 취급하며, 편집 복원은 별도 **이전에 만든 편집 JSON 가져오기**에서 합니다.

파일마다 **텍스트 추출됨 / 원본만 보관 / 추출문만 가져옴**과 읽기 안내를 표시합니다. 추출문을 펼쳐 확인하고 원본 받기·참고에서 빼기를 할 수 있습니다. 여러 파일 중 하나가 실패해도 다른 파일은 보관하고, 실패한 파일은 다시 시도할 수 있습니다. 처리 중 다른 디자인으로의 이동은 막아 업로드 대상이 섞이지 않게 합니다.

PDF·Office·HWPX의 본문 읽기는 **Python 3**을 사용하며 PDF에는 **pypdf**가 필요합니다. 다음은 이 폴더에서 실행하는 최초 준비 명령입니다. macOS/Linux에서는 `python` 대신 `python3`을 사용하세요.

```sh
python -m pip install -r requirements.txt
```

기존 Python과 Codex 번들 Python을 자동 탐색합니다. 경로를 별도로 지정하려면 `DESIGN_PYTHON`에 실행 파일 경로를 넣습니다. 읽기 도구가 없거나 문서를 읽지 못해도 원본은 보관하고 원인 안내를 표시합니다. 스캔 PDF는 OCR하지 않으며, 이미지·도표·복잡한 표 배치·메모·첨부 개체는 해석하지 않습니다. HWP 본문을 읽으려면 HWPX 또는 PDF로 바꾸세요. PDF는 처음 200페이지, 추출문은 파일당 24,000자까지 보관하며 AI 요청에는 합계 60,000자까지만 첨부합니다. 원본 용량·바이트는 변경하지 않습니다.

**참고에서 빼기**는 다음 AI 요청과 내보내기에서 제외하는 동작이며 이 PC의 원본 파일은 보존합니다. ZIP에는 원본을 파일 ID로 구분해 담고 `references/index.json`에 원래 이름·SHA256·읽기 상태를 기록하므로 같은 이름의 파일도 덮어쓰지 않습니다. **JSON 백업·tokens.json에는 참고 문서의 추출문만 포함**합니다. JSON을 새 디자인으로 가져오면 원본 없음이 표시되며 원본을 다시 첨부해야 합니다.

### 로고·심볼과 글꼴을 구체적으로 지정하기

**디자인 규칙 → 로고·심볼**에서 기본 로고, 어두운 배경용 로고, 작은 공간용 심볼을 각각의 큰 업로드 영역에 선택하거나 드래그앤드롭합니다. 본문/제목 글꼴도 별도 영역이며 한 영역에는 파일 하나만 넣습니다. 모두 선택 사항이며 PNG·JPG·WebP 파일당 2 MB까지 지원합니다. 각 원본은 색상·비율을 바꾸지 않고 저장·내보냅니다. 사용 위치·허용 배경·금지 규칙, 상하좌우 보호 여백(px), 로고 최소 가로 너비(px), 심볼 최소 배치 영역(가로×세로 px)을 기록합니다. 크기·여백의 시작값은 실습용 제안이며 공식 브랜드 규격이 아닙니다. 미리보기에서 밝은 배경·어두운 배경·작은 심볼을 따로 확인하세요.

**글꼴**에서는 본문과 제목의 글꼴 이름을 각각 입력하거나 목록에서 선택합니다. 파일 없이 이름만 지정하면 해당 PC의 설치 여부에 따라 시스템 대체 글꼴이 보일 수 있습니다. TTF·OTF·WOFF·WOFF2 원본을 역할별로 하나씩 넣을 수도 있습니다(파일당 5 MB). 업로드 파일의 실제 모양과 지원 굵기를 사용하며, 여러 굵기가 필요하면 가변 글꼴을 권장합니다. 미리보기 하단에서 역할별 파일 로딩 여부를 확인하세요. 기본 Pretendard는 포함돼 있습니다.

본문·제목 굵기(100 단위), 각각의 줄 높이, 입력 제목·주석 크기와 자간을 따로 지정합니다. 글꼴의 출처 주소·라이선스·사용 규칙은 확인한 내용만 직접 기록하세요. 빈 출처와 사용 위치는 미지정으로 남깁니다. 로고와 글꼴 파일 업로드만으로 사용 권한을 확인한 것으로 처리하지 않습니다.

이 값과 원본은 DESIGN.md·tokens.css·tokens.json·ZIP에 함께 담깁니다. 편집 JSON 전체 제한은 32 MB입니다. 업로드된 글꼴은 서버의 .local-data/fonts에 별도 보존하여 매번 자동 저장할 때 큰 파일을 다시 전송하지 않습니다. JSON 백업에는 로고·심볼·글꼴 원본이 포함됩니다. 참고 문서 원본은 ZIP에만 포함하며 JSON에는 추출문만 담습니다. 기존 편집 JSON은 새 항목을 보완해 열고 기존 로고와 글꼴 설정을 유지합니다.

### AI에게 초안 제안받기

이름·목적을 적고 사용할 AI를 선택한 뒤 **AI 초안 제안받기**를 누릅니다. 기획·참고 글·첨부 파일의 추출문·현재 규칙과 추가 요청을 해당 AI 서비스에 전달하며 본인 계정 사용량을 소비합니다. 로고·심볼 이미지와 글꼴 원본 파일은 AI에 전달하지 않고 미리보기·내보내기에 사용합니다. 참고 주소는 출처로 기록할 뿐 자동으로 방문하지 않습니다. 필요한 내용을 참고 글에 붙여 넣으세요.

AI 결과는 별도 **제안**으로 보관합니다. 현재 값과 나란히 비교한 뒤 **이 제안 적용하기**를 눌러야 편집본이 바뀝니다. 요청 이후 편집한 내용이 있으면 경고합니다. 같은 화면에서는 마지막 제안 적용을 한 번 취소할 수 있습니다. 새로고침 후 적용 취소 기록은 유지되지 않으므로 중요한 버전은 JSON 백업도 받아 두세요. AI 호출 중 **중지**할 수 있으며 실패해도 기존 디자인은 보존됩니다. 서버가 다시 켜지면 중단된 작업은 실패 상태로 표시합니다.

## 내보낸 자료로 Codex에서 이어가기

ZIP에는 다음 자료가 포함됩니다.

- `DESIGN.md`: 한국어 디자인 규칙·출처·대비 점검 결과
- `tokens.json`: 이 서비스에서 다시 가져올 수 있는 편집 데이터
- `tokens.css`: 같은 값으로 생성한 CSS 변수
- `preview.html`·`preview-demo.js`: 디자인이 적용된 동작 예시
- `manifest.json`: 자료 형식·버전 정보
- `CODEX-HANDOFF.md`: Codex에 입력할 후속 요청
- `references/`: 첨부한 참고 원본과 파일별 이름·상태·원본 해시 목록
- `assets/`: Pretendard 글꼴·라이선스와 사용자가 넣은 로고·어두운 배경용 로고·심볼·본문/제목 글꼴 원본

**최종 `SKILL.md`는 만들지 않습니다.** ZIP 압축을 푼 폴더를 Codex에서 열고 `CODEX-HANDOFF.md`의 요청으로 스킬을 제작하세요. 제작 서비스의 CODEPLANT 로고를 내 디자인 시스템의 로고로 자동 포함하지 않습니다.

## 저장과 다시 편집하기

편집한 자료는 **`LECTURE_2/.local-data/`**에 자동 저장하며 Git에 포함하지 않습니다. 저장 완료·진행·실패를 상단에서 구분합니다. 다른 탭의 오래된 값으로 저장하면 충돌을 표시하고 덮어쓰지 않습니다. JSON 백업을 받은 뒤 최신 자료를 다시 여세요. 서버 연결이 끊겼을 때도 상단 **JSON 백업**으로 현재 유효한 편집값을 보관할 수 있습니다.

브라우저에도 미저장 편집값의 임시 사본을 남기며 같은 버전이면 다시 열 때 복구합니다. 브라우저 저장 공간이 부족하면 경고합니다. 임시 사본만을 장기 백업으로 사용하지 마세요. 왼쪽 목록에서 다른 디자인을 열거나 **+**로 새 디자인을 만들 수 있습니다. 내보낸 `tokens.json`은 첫 단계의 **편집 JSON 가져오기**로 별도 디자인에 불러옵니다.

서버는 `127.0.0.1`에만 바인딩합니다. API의 Host·Origin과 변경 요청 토큰을 검사하고, 사용자 HTML을 그대로 실행하지 않습니다. 모델은 도구를 사용하지 않는 읽기 전용 호출로 제한합니다. API 키 환경 변수 대신 공식 CLI에 저장된 로그인 사용을 의도합니다. 사용자 계정·개인 자료·AI 응답은 배포 파일에 포함하지 않습니다.
