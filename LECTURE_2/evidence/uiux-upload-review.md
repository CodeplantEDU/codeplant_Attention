# LECTURE_2 참고자료 업로드 독립 UIUX 검수

검수일: 2026-10-21. 실행 주소: `http://127.0.0.1:49323/`. 설치된 Chrome의 별도 Playwright 컨텍스트에서 1440×1000, 390×844 화면을 확인했다. 제품 코드는 수정하지 않았다.

## 판정: PASS — 검수한 업로드 핵심 흐름

검수한 범위의 남은 P1/P2는 없다. 초기 발견한 프로젝트 목록 렌더 함수 누락은 복원 후 실제 초기 화면·저장·목록을 재검수했다. 이 판정은 아래의 확인 범위에 한정한다.

사용자는 참고 PDF·문서·이미지에서 디자인 근거를 모으고, 자신이 가진 로고·심볼·글꼴은 각각의 역할에 지정해야 한다. 따라서 참고 자료의 본문 추출 상태와 원본 보관 여부를 먼저 구분하고, 디자인 자산을 참고 파일과 혼동하지 않도록 별도 영역에 두어야 한다. 현재 화면은 큰 참고자료 영역과 역할별 단일파일 영역을 나누고, 읽지 못한 파일을 읽었다고 표시하지 않는다.

## 이번 확장의 디자인 계약

| 항목 | 확인한 선택 |
|---|---|

| 주요 조작 | 큰 파일 선택 버튼 또는 파일 drop → 파일별 상태 확인 → 추출문 확인/재시도/참고에서 빼기. |

| 편의성 | 참고자료는 다중파일, 역할별 자산은 단일파일로 설명한다. 파일 선택 버튼은 실제 높이 52px였다. |
| 키보드 | 숨겨진 input 대신 보이는 버튼에 포커스하고 Enter/Space로 선택창을 연다. |

| 보존 경계 | 참고 원본은 ZIP, JSON은 이름·추출문 중심이라는 안내를 백업 버튼과 가져오기·내보내기 근처에 둔다. |
| 피할 기본값 | 모든 업로드를 추출 성공으로 표시, 한 파일 실패로 전체 성공분 폐기, 다중파일을 단일 역할에 조용히 덮어쓰기, JSON을 원본 백업처럼 안내. |

## 실제 브라우저에서 확인한 범위

### PDF·TXT 다중 업로드

- 공개 시험용 PDF와 긴 한글 이름의 UTF-8 TXT를 하나의 브라우저 DataTransfer drop 이벤트로 전달했다. 두 파일 모두 실제 서버에 저장됐다.
- PDF의 `[페이지 1] Public review: teal is the main color.` 추출문을 UI에서 열어 확인했다.
- TXT의 한국어 시험 문장과 긴 파일명, 파일별 추출 상태·원본 받기·참고에서 빼기 표시를 확인했다.
- 데스크톱 참고자료 선택 버튼은 높이 52px/너비 약 513px, 모바일은 높이 52px/너비 322px였다.
- 최종 파일 크기 표시 수정 후 새로 열어 612 B·114 B·44.6 KB 등 단위 표시와 초기 오류 없음, 모바일 390px 가로 넘침 없음을 재확인했다. 모바일 캡처는 이 표시로 갱신했다.
- `JSON 백업`의 연결 도움말은 `참고 문서는 추출문만 · 원본은 ZIP`이었다.

시험 PDF는 tests/references.test.mjs의 방식으로 메모리에서 생성한 한 페이지 문서다. 개인·기관의 실제 자료는 사용하지 않았다.

### 원본만 보관하는 파일

- 텍스트가 없는 공개 PDF 시험 파일은 `원본만 보관`, 0자, `스캔 PDF는 OCR 후 올려주세요`로 표시됐다.
- 공개 PNG를 참고자료에 넣었을 때도 `원본만 보관`, 0자, `이미지 내용은 자동 해석하지 않습니다`로 표시됐다.
- 이미지 원본은 로고/심볼 역할에 자동 배정되지 않았다.
- 텍스트 없는 PDF 시험은 OCR 자체를 검사한 것이 아니다. OCR을 실행하지 않는다는 제품 경계를 확인했다.

### 역할별 구분과 잘못된 drop

- PDF를 심볼 영역에 놓으면 PNG·JPG·WebP 제한과 PDF는 참고 문서 영역에 넣으라는 안내가 나왔다. 심볼이 생성되지 않았다.
- 심볼 영역에 PNG 두 파일을 동시에 놓으면 단일파일 안내로 거부했다. 첫 번째 파일만 임의 적용하지 않았다.
- 기본 로고·어두운 배경용 로고·심볼의 서로 다른 세 영역에 각각 이미지 파일을 drop하여 원본 표시를 확인했다.
- 본문과 제목 글꼴의 서로 다른 두 영역에 Pretendard Regular/Bold TTF를 각각 drop했다. 두 역할 모두 업로드 파일 로딩 확인 상태를 표시했다.

검수 자산은 제공된 CODEPLANT 스킬의 공개 브랜드 이미지와 프로젝트에 포함된 Pretendard 파일을 검수자가 명시적으로 선택한 것이다. 사용자 고유 자산이나 기존 프로젝트를 사용하지 않았다.

### 키보드와 모바일

- 큰 참고자료 버튼에 포커스한 뒤 Enter와 Space 각각으로 실제 파일 선택창 이벤트를 열고 TXT 파일을 넣었다. 두 파일의 저장 완료를 확인했다.
- 390px에서 긴 한글 파일명의 카드가 줄바꿈되며 원본 받기·참고에서 빼기가 유지됐다.
- 모바일 문서 너비와 scrollWidth가 모두 390px였다. 긴 이름 카드의 외곽 너비는 354px로 화면 안에 있었다.
- 화면 증거는 작업 영역 중심으로 잘라 기존 프로젝트 목록과 이름이 보이지 않도록 했다.

### ZIP 원본과 JSON 경계

실제 다운로드 ZIP을 메모리에서 해석하여 다음을 확인했다.

- 당시 참고 파일 8개 모두 ZIP 바이트와 원본 API 응답 바이트, 저장된 SHA-256이 각각 일치했다.
- 핵심 PDF와 긴 한글 이름 TXT는 업로드 전 메모리 시험 자료의 바이트와도 동일했다.
- references/index.json의 8개 항목이 해당 원본 파일 경로에 대응했다.
- tokens.json에는 referenceTexts 8개가 있고 참고 원본을 담는 references는 없었다.
- 별도 로고 3종·본문/제목 글꼴의 역할 파일이 함께 포함됐다. SKILL.md는 포함하지 않았다.
- 내보내기 화면에 references/ 및 원본/JSON의 차이 안내가 표시됐다.

### 참고에서 빼기

키보드 Space 시험 TXT를 UI에서 참고에서 뺀 뒤 저장 완료를 확인했다. 서버에 저장된 목록에서 빠졌고, 후속 실제 ZIP의 index에서도 제외됐다. 이후 공개 PNG를 추가한 최종 목록은 8개다. 원본 파일을 물리적으로 삭제하는 동작을 검증한 것은 아니다.

## 모의 실패와 실제 실패를 구분한 확인

| 종류 | 확인한 결과 |
|---|---|
| 실제 형식 실패 | 일반 텍스트를 PDF 확장자로 넣었을 때 실제 서버가 형식 불일치로 거부했다. 정상 TXT는 같은 다중 업로드에서 성공했다. |
| 모의 일시 실패 | 검수 브라우저에서 한 TXT의 첫 업로드 응답만 HTTP 503으로 대체했다. 나머지 정상 파일의 성공분은 유지됐다. |
| 재시도 | 실패 카드의 다시 시도를 누른 두 번째 요청은 실제 서버로 보내 저장 성공을 확인했다. 형식 오류 파일의 실패 카드는 별도로 남았다. |
| 업로드 중 이동 | 파일 처리 중 단계 버튼을 눌렀을 때 0단계를 유지하고 완료 후 이동하라는 안내를 확인했다. |

실제 네트워크 장애·디스크 손상·저장 공간 부족은 만들지 않았다. 모의 응답 실패를 운영 장애 시험처럼 해석하지 않는다.

## 발견 후 수정된 P1

초기 public/app.mjs에 renderProjects() 호출은 있으나 정의가 없어 새 프로젝트 목록이 렌더되지 않았다. API의 프로젝트 생성은 성공했지만 선택 상태 확인 단계에서 진행할 수 없었다. 부모 작업자에게 즉시 보고했고 제품 파일은 직접 수정하지 않았다.

함수 복원 후 실제 초기 화면에서 전역 오류가 없고 프로젝트 버튼 목록이 나타났으며, QA 프로젝트 이름·목적 저장 및 이후 전체 업로드 흐름이 정상 동작했다.

## 미검증과 한계

- OS 탐색기에서 마우스로 실제 파일을 끌어오는 물리 조작은 하지 않았다. 브라우저 DataTransfer drop 이벤트와 이후의 실제 업로드·추출·저장 경로를 검사했다.
- 이 독립 검수의 PDF 본문 시험은 영문 텍스트 PDF다. 한국어 파일명·TXT는 직접 확인했고, 한국어 본문 PDF의 별도 생성·추출 검증은 부모 작업자 범위다.
- DOCX·PPTX·XLSX·HWPX·HWP·CSV·JSON·CSS 각각의 실제 UI 업로드와 모든 손상·암호·대형 문서 조합은 시험하지 않았다.
- 15 MB/20개/60 MB 및 편집 JSON 최대 크기를 실제 UI에서 끝까지 채우지 않았다. 부모 작업자의 자동 테스트와 분리한다.
- 최종 32 MB 편집 JSON/API 제한, legacy 임시 백업 복원 보강은 이 소용량 UI 시험의 직접 검증 범위가 아니다. 서버 최종 재시작 이후의 별도 확인이 필요하다.
- 추가 실제 AI 호출은 하지 않았다. 추출문이 실제 모델의 답변에 어떻게 반영되는지, 제거 자료의 AI 컨텍스트 제외는 이 브라우저 검수에서 새로 호출해 확인하지 않았다.
- 스크린리더 전체 검사, 다른 PC·OS·브라우저·실물 휴대전화, 전체 WCAG 적합성은 보증하지 않는다.

추가 AI 호출과 실제 장애 유발은 생략했다. 검수한 큰 업로드 영역·역할 분리·상태 안내·재시도·모바일·원본 보존 흐름은 PASS이며 위 한계는 남는다.
