# LECTURE_2 독립 UIUX 검수

검수일: 2026-10-20. 대상: `http://127.0.0.1:49323/`. 별도 Playwright/Chrome 컨텍스트에서 1440×1000, 390×844 화면을 사용했다. 제품 코드는 수정하지 않았으며 검수용 프로젝트와 증거 화면만 만들었다.

## 판정: PASS — 검수한 디자인 시스템 제작 핵심 흐름

검수한 범위에서 남은 P1/P2 결함은 발견하지 못했다. 이 판정은 아래 실제 확인 범위에 한정한다. 다른 PC의 CLI 설치, 전체 접근성 적합성, 법률 검토 또는 배포 검증을 의미하지 않는다.

사용자는 자신의 서비스 목적을 적고, 반복해서 사용할 색상·글꼴·여백·한국어 규칙을 결정한 뒤, 적용 화면을 확인하고 Codex에 전달할 자료를 가져가야 한다. 따라서 첫 번째 작업은 기획 입력이며, AI 연결은 보조 수단이다. 현재 화면은 이 순서를 유지한다. 사용자 디자인 자료와 제작 도구의 CODEPLANT 브랜딩, AI 제안과 사용자의 적용 결정, 자료 내보내기와 최종 스킬 제작의 경계가 문장과 행동으로 구분된다.

## 디자인 계약과 비교 근거

| 항목 | 이번 화면의 선택 |
|---|---|
| 사용자와 일 | 한국어 사용자가 자신의 서비스용 디자인 규칙과 전달 자료를 완성한다. |
| 첫 읽기 | 디자인 시스템 이름, 서비스 목적, 현재 제작 단계. |
| 대표 행동 | 기획 입력 후 디자인 규칙으로 이동하고, 화면 확인 후 ZIP을 받는다. |
| 밀도와 계층 | 데스크톱은 편집기와 미리보기를 나란히 두고, 단계·입력명·도움말을 구분한다. |
| 상호작용 | 기획 폼 → 역할별 토큰·규칙 편집 → 상태 미리보기 → 확인 후 자료 내보내기. |
| 좁은 화면 | 단계 탐색을 가로로 바꾸고 편집기 다음에 미리보기를 배치한다. |
| 브랜드 | 제공된 로고, 실제 Pretendard, 단색 표면, teal 행동과 어두운 버튼 글자. |
| 피할 기본값 | 불필요한 지표 카드, 장식용 그라데이션, 사업 사실처럼 보이는 예시 문장, 자동 적용되는 AI 결과. |

비교 자료는 시각 복제가 아니라 아래 편집 원리를 검토하는 데 사용했다.

- [Figma 변수 편집](https://help.figma.com/hc/en-us/articles/15145852043927-Create-and-manage-variables-and-collections): 이름·값·설명을 연결하는 원리 → 한국어 역할명과 용도를 색상값 옆에 둔다.
- [Tokens Studio의 값](https://docs.tokens.studio/manage-tokens/token-values/): 종류마다 허용되는 값이 다르다는 원리 → 색상과 숫자의 입력 검증을 나눈다.
- [Radix Playground](https://www.radix-ui.com/themes/playground): 조절값을 실제 컴포넌트에서 확인하는 원리 → 버튼과 입력창을 직접 조작한다.
- [Carbon 색상 가이드](https://www.carbondesignsystem.com/building-blocks/foundations/color/guidelines): 역할별 토큰 적용 원리 → 대표색·본문·표면·경계 등 쓰임을 기록한다.

## 실제 동작으로 확인한 범위

| 확인 | 관찰 결과 |
|---|---|
| 기획 및 단계 이동 | 빈 필수 이름으로 다음 단계 이동 시 한국어 안내와 이름 입력란 포커스. 이름·목적 입력 후 단계 이동 가능. |
| 저장과 재진입 | 저장 완료 표시, 새로고침 후 선택한 검수 프로젝트와 정상 저장 표시 유지. |
| 실제 토큰 반영 | 대표색 `#315987` 편집 후 iframe 버튼 배경 `rgb(49, 89, 135)` 확인. |
| 미리보기 | 대표 버튼 클릭 시 피드백 출력. 390px에서도 미리보기 제목·버튼·카드가 실제 렌더됨. |
| 글꼴 | 최신 서버에서 iframe의 Pretendard Regular/Bold 두 face가 모두 `loaded`. 최종 재검수 콘솔 오류 0. |
| 잘못된 입력 | `#XYZ`, 본문 크기 `99`, 잘못된 참고 주소를 각각 차단. 참고 주소에는 전용 한국어 안내와 `aria-describedby` 연결 확인. |
| 키보드 | 최초 Tab의 본문 건너뛰기, Enter의 main 포커스, 보이는 포커스 외곽선, 연결 모달의 Escape 닫기 확인. 규칙 탭 ArrowRight·Home·End 이동 확인. |
| 가로 넘침 | 수정 후 데스크톱 문서 너비 1440/뷰포트 1440, 모바일 문서 너비 390/뷰포트 390. |
| 내보내기 | 확인 체크 전 다운로드 비활성. 실제 브라우저 다운로드의 ZIP을 메모리에서 읽어 파일명·JSON/CSS 색상 일치·SKILL.md 미포함 확인. |
| 자료 구성 | DESIGN.md, tokens.json, tokens.css, preview.html, CODEX-HANDOFF.md, manifest.json, 폰트·라이선스, preview-demo.js 확인. |
| 가져오기 | 편집 JSON을 새 검수용 이름으로 열기, 참고 MD의 파일명·내용 추가, 테스트 PNG의 정상 디코딩 확인. |
| AI 제안 확인·적용·취소 | 별도 허용된 공개 검증용 Codex 프로젝트에서 변경 2항목 비교 화면 → 적용 → 취소 수행. API 재조회로 취소 후 디자인 JSON이 적용 직전과 정확히 같음을 확인. |
| 연결 UI | 두 CLI의 설치·로그인 표시와 실제 응답은 요청 때 확인한다는 문구, 로그인 명령·공식 안내·설치 경로 화면 확인. |

## 모의 실패로 확인한 범위

실제 디스크를 손상시키거나 서버를 중단하지 않았다. 검수 브라우저 안에서 저장 PUT 응답을 HTTP 500으로 대체했다. 이때 입력값 유지, `저장 실패 · JSON 백업 가능` 표시, 한국어 오류 안내, 내려받은 JSON 백업 안의 편집값 보존을 확인했다. 이후 가로채기를 해제하고 입력을 원래 값으로 돌려 저장했다.

초기 검수 중 새로고침이 최신 프로젝트를 여는 동작 때문에 저장 실패 모의가 공개 Claude 검증 프로젝트에서 한 차례 진행됐다. 해당 입력값은 즉시 원래 값으로 복원했다. 이후 선택 프로젝트 복원이 추가되어 재검수 통과했다.

## 발견 후 수정 및 재검수된 결함

| 초기 결함 | 수정 후 증거 |
|---|---|
| 숨김 파일 입력이 전체 화면 폭을 받아 1440px 화면의 문서 폭이 1921px로 증가 | 수정 후 1440px와 390px 모두 문서 가로 넘침 없음. |
| sandbox 미리보기에서 폰트 CORS 차단, 예시 버튼 무반응 | 두 폰트 face loaded, 버튼 피드백, 콘솔 오류 0. |
| 잘못된 참고 주소에도 색상·숫자 오류 문구 출력 | 주소 전용 inline·전역 오류와 복구 방법 표시. |
| 정상 저장 후 새로고침을 미저장 복구로 오판 | 같은 프로젝트 이름과 `이 PC에 저장됨` 유지. |
| 새로고침 때 다른 최신 프로젝트를 열음 | 선택한 프로젝트 유지. |
| ARIA 탭에 방향키 동작이 없음 | ArrowRight→글꼴, End→사용 규칙, Home→색상 이동. |

## 미검증과 적용 한계

- 독립 검수자는 실제 AI 생성 요청을 새로 보내지 않았다. 부모 작업자의 Codex/Claude 생성 성공 보고와 별도로, 여기서는 이미 완료된 Codex 결과의 비교·적용·취소만 직접 검증했다.
- CLI 미설치·로그아웃 상태의 실제 OS 환경, 새 사용자 계정, 다른 PC, macOS/Linux, 실물 휴대전화, 다른 브라우저는 시험하지 않았다.
- 실제 저장 공간 부족·권한 거부·전원 종료를 발생시키지 않았다. 저장 실패 확인은 응답 가로채기 방식이다.
- 스크린리더 전체 사용성, 200% 확대, 전체 WCAG 적합성, 모든 색상 조합의 접근성은 보증하지 않는다.
- 다운로드 ZIP 내용은 직접 확인했지만, 압축 해제된 file:// 미리보기의 독립 실행 검증은 부모 작업자 범위다.
- 저작권에 대한 법률 판단, 최종 스킬 생성, 외부 배포, 실제 수업 운영은 이 검수에 포함하지 않는다.
- 1차 조회에서 사용한 과거 브랜드 메모 대신 현재 공식 codeplant-design 스킬 및 실제 자산·화면을 최종 판단 근거로 삼았다.

범위 밖 검증과 실제 장애 유발은 생략했다. 위 한계를 포함한 핵심 제작 흐름에 대한 PASS이며 서비스 전체 무결함 인증은 아니다.
