# 2시간 핵심 시연형 운영안

주제: 한 AI가 다른 AI를 불러 대화하고, 반론을 반영해 결과를 고치는 과정.

대상은 AI를 처음 쓰거나 개별 챗봇 사용 경험이 있는 성인입니다. 아래 시간표는 사용자의 2시간 핵심 시연형 요청에 맞춘 교육 설계이며 효과 검증 결과가 아닙니다.

## 수업 후 할 수 있는 것

- 메인 AI·서브 에이전트·상대 AI의 차이를 화면의 실제 기록으로 설명한다.
- 공개 자료를 올리고, 두 AI의 검토를 거친 결과와 원문을 대조한다.
- 후속 질문을 보내 수정 이유와 사람이 결정할 사항을 구분한다.
- README의 시작문으로 같은 프로그램을 다시 실행한다.

## 시간표

| 시간 | 진행 | 보여줄 결과 |
|---|---|---|
| 0~10분 | 오늘의 과제와 완성 화면 소개 | 공개 실습 조건, 작업 기록, 최종 답변 |
| 10~25분 | Codex에서 README로 실행·로그인 상태 확인 | 로컬 화면, 두 연결 상태 |
| 25~40분 | 파일 드래그앤드롭·추출 미리보기·지시 작성 | 자료 선택과 원문 조건 확인 |
| 40~65분 | Codex 메인·양쪽 역할 편집·각자 내부 역할 설정·Claude 검토 시연 | 실제 내부 에이전트, 반론, 메인 판단 |
| 65~80분 | 같은 대화에 후속 질문 | 이전 대화를 반영한 수정과 보류 이유 |
| 80~95분 | Claude 메인으로 새 작업 비교 | 반대 방향 실행, 결과 차이에 대한 관찰 |
| 95~105분 | CLI·MCP·GitHub·자료 이동 설명 | 로컬 서비스와 정적 자료 화면 차이 |
| 105~115분 | 참가자 과제 적용문 작성·기록 내보내기 | 자기 과제용 지시와 Markdown 기록 |
| 115~120분 | 사람의 근거 확인·질의·다음 실행 | 출처 대조, 미확인 항목과 다음 행동 |

합계 120분. 라이브 응답 시간은 일정하지 않으므로 대기 중에는 원문 대조와 반론 판정 활동을 진행합니다. 연결이 실패하면 실패 상태를 보여준 뒤, 미리 저장한 기록임을 밝히고 재생합니다. 실제 실행처럼 설명하지 않습니다.

## 강사 준비

1. 두 CLI가 설치·로그인됐는지 사이트에서 확인합니다. 로그인 정보가 화면에 보이지 않게 합니다.
2. `examples/공개_실습자료.md`를 사용합니다. 개인·고객 자료로 시연하지 않습니다.
3. `Codex에_이렇게_입력.md`의 시작문을 별도 창에 준비합니다.
4. 완료 기록과 `site/evidence`의 실제 캡처를 준비합니다. 기록 화면은 당시 실행 결과라는 점을 표시합니다.
5. 첫 실행은 메인 내부 역할 1~2개·상대 내부 역할 0~1개·왕복 1회로 진행합니다. 응답 실패를 성공으로 숨기지 않습니다.

## 시연 멘트와 행동

**시작:** “제 지시는 한 곳에 쓰고, 메인 AI가 다른 AI의 반론을 받아 고치게 해보겠습니다. 지금 선택한 메인과 내부 역할, 상대 AI를 구분해 보세요.” 메인 라디오·역할 카드·대화 순서를 짚습니다.

**자료:** “파일을 이 영역에 끌어놓으면 우선 이 PC에서 글을 읽습니다. 여기 보이는 추출문이 모델에게 전달할 내용입니다.” 미리보기를 펼쳐 원문과 비교하고, 대화 시작을 누를 때 외부 전달이 이뤄짐을 안내합니다.

**내부 역할:** “양쪽 AI의 역할을 고른 뒤 직접 수정할 수 있고, 하위 역할도 각각 추가할 수 있습니다. 오른쪽 상태는 역할 이름만 말한 결과가 아니라 실제 생성·완료 이벤트입니다.” 역할별 회신을 읽고 어느 AI의 하위 역할이 무엇을 확인했는지 묻습니다.

**다른 AI:** “이제 상대 AI가 초안을 읽습니다. 동의가 목표는 아닙니다.” 반론 중 하나를 골라 원문 근거가 있는지 청중과 판단합니다.

**후속:** “새 채팅에 처음부터 묻지 않고, 이 작업의 맥락을 이어 수정하겠습니다.” 자료의 누락 조건을 짚어 질문하고, 기존 답과 바뀐 답을 대조합니다.

**마무리:** “AI끼리 검토해도 틀릴 수 있습니다. 원문 확인과 최종 판단은 사람이 합니다.” 내보내기로 기록을 저장하고 다음 실행용 README를 엽니다.

## 관찰 활동 3문항

1. 자료 [F1]의 필수 조건이 최종 결과에 모두 있는가?
2. 상대 AI의 반론 중 수용·반박·보류한 이유가 보이는가?
3. 확인된 사실과 새 제안, 사람에게 남은 선택이 구분되는가?

## 실패 시 복구

로그인 실패 → 공식 CLI에서 본인 로그인 후 새로 확인. 모델 오류 → 모델 이름을 비워 기본값으로 재실행. 스캔 PDF → 텍스트 자료로 바꾸거나 OCR한 뒤 올림. 작업이 길어짐 → 중지 후 범위를 줄인 새 작업. 후속 대화가 너무 김 → 기록을 내보내 필요한 내용을 요약해 새 작업.

이전 28장 PPTX·PDF는 `materials/이전강의_참고본`에 보존했습니다. 해당 자료의 Gemini·수동 전달 도구 설명은 이전 구성입니다. 현재 시연은 이 운영안과 두 모델 사이트를 기준으로 합니다.
